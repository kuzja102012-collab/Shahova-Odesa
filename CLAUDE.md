## 2. ПОТОЧНИЙ СТАН

Сайт **готовий і працює**. Це не чернетка — це робоча версія, яку можна
викладати на хостинг хоч сьогодні.

```
site/index.html       — увесь сайт одним файлом (розмітка + стилі + скрипт + контент)
site/site-data.json   — той самий контент окремо; на хостингу його оновлює кнопка «Опублікувати»
site/publish.php      — єдиний серверний файл: приймає зміни й файли з редактора (PHP 7.4+)
site/publish-config.php — пароль публікації (порожній = публікацію вимкнено)
site/assets/          — логотип організації та іконки
site/assets/photos/   — фото новин за місяцем публікації (YYYY-MM/), мініатюри — у YYYY-MM/t/
site/assets/scans/    — протоколи й таблиці-зображення (Swiss-Manager, турнірні таблиці)
site/assets/docs/     — регламенти (JPG/PDF), за місяцем публікації (YYYY-MM/)
site/.htaccess        — переадресація зі старих адрес WordPress (хостинг LiteSpeed)
site/README.txt       — коротка інструкція для замовника
migration/            — одноразові скрипти перенесення (14.10.2026); на хостинг НЕ викладати
```

**Без бази даних і збірки.** Відкривається подвійним кліком із файлової
системи. Для викладання — скопіювати `index.html`, `site-data.json`,
`publish.php`, `publish-config.php`, теку `assets` і `.htaccess` у кореневу
теку хостингу й вписати пароль у `publish-config.php`.

**Єдиний виняток з правила «без PHP» — `publish.php`** (рішення автора
14.10.2026: клуб має публікувати новини сам, кнопкою «Опублікувати»).
Він нічого не генерує на льоту: лише записує `site-data.json`, оновлює
копію даних в `index.html`, приймає фото/документи в `assets/…/РРРР-ММ/`
і зберігає 60 попередніх версій у `_private/backups/` (тека закрита
`.htaccess`). Захист: пароль з `publish-config.php` у кожному запиті,
блокування після 10 невдалих спроб за 15 хв, перевірка походження запиту,
тип файлу — за вмістом (JPG/PNG/WebP/PDF/DOC(X)/XLS(X)), назви файлів
генерує сервер. Без PHP сайт працює так само, лише без публікації.

### Фото й документи — лише локально

Усі фото й регламенти лежать у `assets/` (скопійовані зі старого сайту
14.10.2026) і підключаються відносними шляхами. **Не посилатися на
`chessclub.com.ua/wp-content/...`** — після заміни сайту цих файлів не буде.
Нові файли класти в `assets/photos|scans|docs/YYYY-MM/` з латинськими
назвами (кирилиця в назвах файлів ламається при FTP/zip). Фото галереї —
до ~1024 px, плюс мініатюра ~300 px у `YYYY-MM/t/`; протоколи — в оригіналі.
Редактор робить це сам: фото — 1600 px + мініатюра 480 px (JPEG), протоколи —
2400 px; назву файлу бере з транслітерованого заголовка новини.

`.htaccess` веде старі сторінки (`/турніри/`, `/контакты/`, `/архів-новин/`…)
на розділи й матеріали нового сайту, а старі адреси файлів `wp-content/uploads/…`
(і зменшені копії WordPress `-300x200`) — на копії в `assets/`.
Перелік старих сторінок узято з `wp-sitemap.xml` старого сайту.

## 3. АРХІТЕКТУРА

Односторінковий застосунок на чистому JavaScript, без фреймворків і
залежностей. Роутинг через `location.hash`.

```
#/                    головна
#/news                новини (вкладки за роками)
#/news?year=2025      новини конкретного року
#/news/<id>           сторінка новини
#/tournaments         анонси турнірів
#/tournaments?tab=results&year=2025   результати за роками
#/tournaments?tab=champions           «Зала чемпіонів»
#/players             шахісти (?q=пошук, ?f=fide|champ, ?s=std|rapid|blitz|n)
#/players/<id>        сторінка шахіста
#/about               про нас
#/contacts            контакти + карта Google
#/search?q=<запит>    пошук (зокрема шахісти)
#/editor              редактор сайту (пароль — у publish-config.php на хостингу)
```

Увесь контент — в об'єкті `const DATA = {...}` всередині `<script>`.
`site-data.json` — його точна копія. На хостингу сторінка після завантаження
перевіряє `site-data.json`: якщо його `updated` новіший (опублікували з
редактора), підставляє свіжі дані. Блок даних в `index.html` закінчується
рядком `};` — за маркером `\n};\n` його знаходять і `publish.php`, і `build.js`.

### Структура даних

```js
DATA = {
  news: [{
    id, date, dateNote, year, title, lead,
    sortDate,                                             // лише для сортування, якщо дата невідома
    body:   ["абзац", "## підзаголовок", "• пункт списку"],
    tables: [{title, head:[...], rows:[[...]]}            // проста таблиця
            {title, groups:[{label, head, rows}]}],       // таблиця з групами (тури)
            // додано через редактор: final:true, label, disc, date — підсумкова таблиця,
            // рядки якої (стовпець «Учасник») потрапляють на сторінки шахістів
    photos: [{src, thumb, caption}],                      // галерея (мініатюра + перегляд на весь екран)
    scans:  [{src, caption}],                             // протоколи й таблиці-зображення
    docs:   [{title, url}],                               // регламенти, PDF
    related:["id-іншої-новини"],                          // пов'язані матеріали
    status: "Перевірено" | "Архівні дані" | "Потребує уточнення",
    needsCheck: "",                                       // текст застереження (жовта плашка)
    sourceNote: ""                                        // звідки матеріал (Web Archive, переклад тощо)
  }],
  announcements: [{id, newsId, title, dateStart, dateEnd, place,
                   discipline, format, ageCat, lead, regulation}],
  results: [{id, newsId, year, dateStart, dateEnd, title, discipline,
             kind: "champ"|"semi"|"tourn"|"qualif"|"team",
             groups:[{label, places:[{p, name, pts}], noChampion}],
             status, note}],
  contacts: {address, hours, email, phone, facebook, telegram, mapQuery},
  about:    {title, body:["абзац"]},
  updated:  "2026-10-14T14:54:32Z",                       // мітка версії (build.js / publish.php)
  fideDate: "2026-10",                                    // місяць списку рейтингів FIDE
  events:   [{newsId, label, date, disc, of, approx}],    // змагання з підсумковими таблицями
  players:  [{id, name, aliases:[...],                    // написання з протоколів і повідомлень
              apps: [[№ в events, місце, очки, рейтинг у протоколі, 1=титул чемпіона, "приз за категорією"]],
              fide: {id, name, title, std, rapid, blitz, inactive}}]   // fide — лише якщо знайдено
}
```

**Шахісти** — генерується скриптом `migration/players.js` (його викликає
`build.js`): підсумкові таблиці зі списку `players-spec.js` + призери з
`results`; написання зводяться (латиниця протоколів ↔ кирилиця повідомлень,
одруки), ручні рішення — у `players-spec.js` (`sameAs`, `keepApart`, `display`,
`rename`, `fide`). Зіставлення з FIDE — за повним списком рейтингів FIDE
(жовтень 2026, лише UKR): точне написання → нормалізоване → «скелет» з ≤2
відмінностями; тезок розводить близькість рейтингу. Звіт для перевірки —
`node players.js` → `players-report.txt`. Призове місце — з офіційних підсумків
(`results`), бо в протоколі однакові очки показано спільним місцем «2–5».
**Звірка з FIDE (14.10.2026, на прохання автора — «перевір усі фідешні»).**
Для кожного профілю завантажено офіційну історію рейтингу з ratings.fide.com
(`fidecheck/fetch-hist.js`, POST `a_chart_data.phtml?event=ID&period=0` — те
саме, що графік на сторінці профілю; пауза 1,5 с між запитами, інакше FIDE
віддає порожні відповіді). `fidecheck/verify.js` порівнює рейтинг у протоколі
кожного виступу з рейтингом FIDE того місяця. Підсумок: 300 шахістів з
профілем FIDE (було 271), з них 229 підтверджені рейтингом, 71 — за ім'ям
(`fide.m = 'n'`, на сторінці — примітка «зіставлено за ім'ям… якщо це не ви —
напишіть нам»). З 1004 рейтингів у протоколах FIDE-змагань 994 збіглися з
FIDE того місяця, 7 — з попереднім (у протокол потрапив список попереднього
місяця), 3 одиничні розбіжності — у гравців, підтверджених іншими турнірами.
- **Національні, а не FIDE-рейтинги** — у протоколах півфіналу 2020/21,
  Меморіалу Постола 2020 (класика) і фіналу до 20 років (грудень 2023):
  на 150–450 вищі за FIDE. «1900» у півфіналі й Постолі — умовне значення.
- **Інші федерації** (запис `fide.fed`, підказка «Грає за федерацію…»):
  Кислинський (CZE, GM), Бохнак (CZE, FM), Горошков (SLO, FM), Кукелко (SVK, FM),
  Гризлова (SUI, WIM), Чуравін (ENG), Байдецький (AUT, GM), Клінова (ISR, IM),
  Легкий (FRA, GM), Максимович (SRB), Холодзінські (KAZ), Пустовий (GER),
  Bar Abadi (IRI). Їхні записи — `fidecheck/fide-extra.json` (у збірці — `fide/extra.json`).
- Графік на сторінці шахіста з профілем FIDE — **офіційна історія FIDE по
  місяцях** з 2020 року (`players[].fh = {s|r|b: [[РРММ, рейтинг]]}`, лише місяці
  змін, сходинками). Без профілю — як раніше, з рейтингів у протоколах.
- Рішення й причини — коментарі в `players-spec.js` (`fide`, `tableRename`,
  список свідомо не зіставлених тезок).

Щоб оновити рейтинги FIDE: завантажити свіжий `players_list.zip` з
ratings.fide.com/download, витягти UKR (`fide/extract-ukr.js`), змінити
`FIDE_DATE` у `players.js`, видалити `fidecheck/hist/` і заново запустити
`fetch-hist.js` (історія), потім `verify.js` (звірка) і перезібрати. Таблиці, додані через редактор із
позначкою «підсумкова», підхоплюються на сторінках шахістів і без перезбирання
(за точним збігом імені з `aliases`; нові імена — після перезбирання).

`discipline`: `classic` | `rapid` | `blitz` (або порожньо).

**Статуси:** «Перевірено» — перенесено з чинного старого сайту; «Архівні дані» —
відновлено з Web Archive або з docx-архівів; «Потребує уточнення» — є суперечність.

**Результати й чемпіони.** Вкладка «Чемпіони» будується автоматично:
`kind:"champ"`, група без `noChampion`, учасник з `p:"1"`. Імена — як у джерелі
(з протоколів Swiss-Manager латиницею, з повідомлень — українською).
Місця в межах однакових очок — за порядком у протоколі, про це сказано в `note`.

## 4. ПРАВИЛА РОБОТИ З ДАНИМИ — найважливіше

Це шаховий архів реальної організації. Дитячі змагання, прізвища дітей,
очки, розряди. Помилка в прізвищі чи цифрі б'є по конкретній людині.

### Заборонено

- **Вигадувати будь-що**: новини, прізвища, рейтинги, результати, дати,
  контакти, турніри. Жодних «приблизно», жодних правдоподібних заглушок.
- **Видавати історичні дані за актуальні.** Рейтинг 2023 року — це рейтинг
  2023 року, а не поточний.
- **Змішувати типи даних.** Перемога в турнірі ≠ перше місце в рейтингу.
- **Плутати фото різних турнірів і років.**
- **Домальовувати демо-дані** в порожні розділи.

### Якщо дані нечіткі або суперечливі

Ставити статус `Потребує уточнення` і писати, чого саме бракує.
Краще чесний прочерк, ніж вигадане число.

### Як перевіряти

Звіряти між собою: текст новини ↔ таблиця на фото ↔ інші матеріали того
самого турніру. Для таблиць є машинна перевірка: сума очок усіх
учасників дорівнює `кількість_учасників × кількість_турів ÷ 2` (за непарної
кількості — з урахуванням пропуску туру). Розбіжність — сигнал звірити з
протоколом, але не доказ помилки: вибулі гравці й поразки без гри дають
меншу суму в самому протоколі (так у Геллері 2026 — 129, у півфіналі U20 2023).

Типова помилка зчитування з зображень — **загублений нуль у Бухгольці**
(«50.5» → «5½»). Шукати значення, що різко менші за сусідні.

## 8. ЯК ПРАЦЮВАТИ ДАЛІ

- Правки **точкові**. Проєкт не переписувати з нуля — замовник економить
  ліміти й не хоче переписування того, що вже узгоджено.
- Після кожної зміни `index.html` перевіряти синтаксис скрипта
  (`node --check`) і прогін усіх розділів — у файлі ~730 КБ, одна зламана
  лапка кладе весь сайт.
- Контент міняти **синхронно** в `index.html` і `site-data.json`.
- **Після передачі сайту клубу головне джерело контенту — хостинг**: редактори
  публікують туди. Перед будь-якою правкою розробника спершу забрати з хостингу
  свіжі `site-data.json` та `assets/`, інакше перезбирання зітре їхні публікації.
- Не додавати залежностей, збірку, бекенд. Один файл — це свідоме рішення,
  а не тимчасове. Єдиний виняток — `publish.php` (див. розділ 2).
- Чого точно не робити: LIVE-трансляції, суддівська панель, генератор пар,
  введення результатів наживо, особистий кабінет. Замовник це скасував.
